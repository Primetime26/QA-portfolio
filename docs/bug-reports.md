# Примеры баг-репортов

Ниже показан формат оформления дефектов. Это **демонстрационные примеры**, а не утверждение о текущих дефектах DummyJSON.

## BUG-EXAMPLE-001 — API возвращает `500` для нечислового ID

| Поле | Значение |
| --- | --- |
| Тип | функциональный |
| Severity | Major |
| Priority | High |
| Окружение | Demo API, test environment, Postman 11.x |
| Предусловие | API доступен |

**Шаги:**

1. Отправить `GET /products/abc`.
2. Проверить HTTP-код и тело ответа.

**Фактический результат (пример):** сервер возвращает `500 Internal Server Error` и stack trace.  
**Ожидаемый результат:** клиентская ошибка `400`/`404` с безопасным JSON-сообщением; внутренние детали не раскрываются.  
**Воспроизводимость:** 5/5.  
**Вложение:** добавить экспорт запроса/ответа или скриншот из Postman перед регистрацией реального дефекта.

## BUG-EXAMPLE-002 — Параметр `limit=1` не ограничивает выдачу

| Поле | Значение |
| --- | --- |
| Тип | функциональный |
| Severity | Minor |
| Priority | Medium |
| Окружение | Demo API, test environment, Postman 11.x |
| Предусловие | В каталоге больше одного товара |

**Шаги:**

1. Отправить `GET /products?limit=1`.
2. Посчитать элементы в массиве `products`.

**Фактический результат (пример):** массив содержит 30 товаров, поле `limit` равно `30`.  
**Ожидаемый результат:** массив содержит один товар, поле `limit` равно `1`.  
**Воспроизводимость:** 5/5.  
**Дополнение:** приложить полный response body и время запроса.

## Шаблон для реального дефекта

- Краткий заголовок: где, что происходит и при каком условии.
- Окружение и версия сборки.
- Предусловия и минимальные шаги воспроизведения.
- Фактический и ожидаемый результаты без двусмысленности.
- Severity, priority и воспроизводимость.
- Доказательства: запрос, ответ, логи, скриншот или видео без чувствительных данных.
