# Тест-план: DummyJSON Products API

## 1. Цель

Проверить основные операции Products API, обработку ошибочных запросов и стабильность контракта ответа, а также подготовить набор проверок для регулярного запуска в CI.

## 2. Объём

В объёме:

- `GET /products`;
- `GET /products/{id}`;
- `GET /products/search`;
- `POST /products/add`;
- `PATCH /products/{id}`;
- `DELETE /products/{id}`;
- query-параметры `limit`, `skip`, `select`, `q`;
- HTTP-коды, JSON-схема ключевых объектов и время ответа.

Вне объёма:

- нагрузочное и security-тестирование;
- внутреннее устройство сервиса и БД;
- реальное сохранение изменённых данных — сервис его не поддерживает;
- UI и мобильные клиенты.

## 3. Подход

1. Проанализировать публичную документацию.
2. Выделить позитивные и негативные классы для ID и query-параметров.
3. Составить чек-лист и приоритетные тест-кейсы.
4. Автоматизировать стабильные проверки в Postman.
5. Запускать коллекцию Newman локально и в GitHub Actions.

## 4. Окружение

| Компонент | Значение |
| --- | --- |
| Base URL | `https://dummyjson.com` |
| Клиент | Postman / Newman 6.2.1 |
| Формат данных | JSON |
| CI | GitHub Actions, Ubuntu, Node.js 20 |

## 5. Приоритеты

- **P0:** сервис доступен, список и товар по ID возвращаются корректно.
- **P1:** CRUD-имитации и обработка неизвестного ID.
- **P2:** поиск, пагинация, выбор полей и мягкая проверка времени ответа.

## 6. Риски

| Риск | Влияние | Снижение риска |
| --- | --- | --- |
| Публичный сервис временно недоступен | ложное падение CI | повторный ручной запуск, проверка статуса сервиса |
| Тестовые данные меняются | хрупкие проверки | проверять контракт и свойства, а не полный ответ |
| API изменяет контракт | падение схемы | сверить документацию и зафиксировать изменение |
| Операции записи не сохраняются | неверная трактовка результата | явно исключить персистентность из объёма |

## 7. Критерии начала и завершения

Начало:

- документация доступна;
- base URL отвечает;
- Postman-коллекция импортируется без ошибок.

Завершение:

- все P0/P1 проверки выполнены;
- все автотесты проходят в локальном запуске и CI;
- найденные отклонения зарегистрированы с шагами и доказательствами;
- ограничения проекта отражены в README.
