# Обзор демонстрационного проекта

## Цель

Показать подход к тестированию REST API каталога товаров: от анализа требований и выбора проверок до автоматизированного запуска в CI.

## Объект тестирования

Публичный учебный сервис [DummyJSON Products API](https://dummyjson.com/docs/products).

Проверяемые операции:

- получение списка товаров и одного товара;
- пагинация и выбор полей;
- поиск товаров;
- создание, изменение и удаление товара;
- обработка запроса несуществующего ресурса;
- базовая структура и типы данных ответа.

## Важное ограничение

`POST`, `PUT`, `PATCH` и `DELETE` в DummyJSON только имитируют изменение данных. Результат возвращается в ответе, но не сохраняется. Поэтому проверка персистентности не входит в объём проекта.

## Артефакты и трассировка

| Требование | Проверка | Автоматизация |
| --- | --- | --- |
| Получить список товаров | API-01, TC-API-001 | `Products / Get products with pagination` |
| Получить товар по ID | API-02, TC-API-002 | `Products / Get product by id` |
| Обработать неизвестный ID | API-03, TC-API-003 | `Products / Product not found` |
| Создать товар | API-04, TC-API-004 | `Products / Add product` |
| Частично изменить товар | API-05, TC-API-005 | `Products / Update product` |
| Удалить товар | API-06, TC-API-006 | `Products / Delete product` |

## Критерий качества ответа API

- HTTP-код соответствует сценарию.
- Ответ является валидным JSON.
- Обязательные поля присутствуют и имеют ожидаемые типы.
- Переданные значения корректно отражаются в ответе на операции изменения.
- Время ответа контролируется мягким порогом 2 секунды без смешивания функционального и нагрузочного тестирования.

## Что не заявляется

Проект не содержит результатов тестирования коммерческих систем, данных работодателя или вымышленных метрик. Баг-репорты в репозитории — примеры структуры документа и помечены как демонстрационные.
