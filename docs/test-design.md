# Тест-дизайн

## Идентификатор товара `{id}`

| Класс | Пример | Ожидаемый результат |
| --- | ---: | --- |
| Существующее целое положительное значение | `1` | `200`, объект товара с соответствующим `id` |
| Несуществующее целое положительное значение | `999999` | `404`, сообщение об отсутствии ресурса |
| Ноль | `0` | ошибка отсутствующего ресурса |
| Отрицательное целое | `-1` | ошибка отсутствующего ресурса |
| Строка | `abc` | ошибка валидации или отсутствующего ресурса без `5xx` |
| Пустой сегмент | `/products/` | список товаров; это другой маршрут |

Границы для положительного ID: `0 / 1 / 2`. Конкретная верхняя граница набора данных может меняться, поэтому тест не привязан к последнему ID.

## Параметр `limit`

| Класс | Пример | Ожидаемый результат |
| --- | ---: | --- |
| Минимальное полезное значение | `1` | один товар |
| Типичное значение | `5` | не более пяти товаров |
| Специальное значение | `0` | все товары согласно документации |
| Отрицательное значение | `-1` | предсказуемая клиентская ошибка либо документированная нормализация, без `5xx` |
| Нечисловое значение | `abc` | предсказуемая клиентская ошибка либо документированная нормализация, без `5xx` |

## Параметр поиска `q`

| Класс | Пример | Ожидаемый результат |
| --- | --- | --- |
| Существующее слово | `phone` | список содержит совпадения |
| Несуществующая последовательность | `zzzz-no-match` | пустой список, `total = 0` |
| Пустая строка | `` | документированное поведение без `5xx` |
| Спецсимволы | `%25_%2F` | корректная обработка URL-кодирования без `5xx` |

## Цена при создании товара

| Класс | Пример | Проверка |
| --- | ---: | --- |
| Положительное целое | `100` | значение возвращено числом |
| Положительное дробное | `19.99` | точность не потеряна |
| Ноль | `0` | проверить продуктовые ограничения |
| Отрицательное | `-1` | проверить наличие или отсутствие валидации |
| Строка вместо числа | `"19.99"` | проверить типизацию контракта |
| Поле отсутствует | — | проверить обязательность поля |

Автоматизация покрывает стабильный позитивный класс. Спорные ограничения вынесены в ручные исследовательские проверки, потому что публичная документация не задаёт бизнес-валидацию цены.
